# بک‌آپ و بازگردانی

همه‌ی داده‌ی این پروژه در یک جا است: دیتابیس D1 با نام `sobhan-bot-db`.
لیدها، شماره‌ها، مشترکین تقویم، حساب‌های پنل، محتوا — همه آنجاست. کد روی
گیت‌هاب نسخه‌بندی شده و نیازی به بک‌آپ جدا ندارد.

محافظت دو لایه است، چون دو خطرِ متفاوت وجود دارد و هیچ‌کدام دیگری را
پوشش نمی‌دهد.

## لایه‌ی اول: Time Travel

D1 خودش تا ۳۰ روز گذشته را نگه می‌دارد و می‌شود دیتابیس را به هر
لحظه‌ای برگرداند. هیچ تنظیمی لازم ندارد و همین حالا فعال است.

این لایه برای محتمل‌ترین خطر است: یک حذف اشتباه، یک مهاجرت خراب، یک
اسکریپت که بیشتر از آنچه باید نوشت.

```
npx wrangler d1 time-travel restore sobhan-bot-db --timestamp=2026-09-01T07:00:00Z
```

پیش از بازگردانی، اول بدون اجرا ببینید به کجا برمی‌گردید:

```
npx wrangler d1 time-travel info sobhan-bot-db --timestamp=2026-09-01T07:00:00Z
```

## لایه‌ی دوم: نسخه‌ی هفتگی روی گیت‌هاب

Time Travel داخل همان حساب Cloudflare است. اگر حساب از دست برود، هم
دیتابیس می‌رود هم نسخه‌ی بازگردانی‌اش. برای همین یک نسخه بیرون از
Cloudflare لازم است.

جاب `.github/workflows/db-backup.yml` جمعه‌ها ساعت ۰۳:۰۰ UTC اجرا
می‌شود، دیتابیس را export می‌کند، با AES-256 رمز می‌گذارد و در یک مخزن
**خصوصی** جدا می‌گذارد. دوازده نسخه‌ی آخر (سه ماه) نگه داشته می‌شود.

پیش از ذخیره، دامپ بررسی می‌شود: اندازه‌اش معقول باشد و جدول‌های اصلی
داخلش باشند. یک فایل نصفه هم «موفق» به نظر می‌رسد و بی‌صدا جای نسخه‌ی
سالم قبلی را می‌گیرد — و این را فقط روزی می‌فهمیم که به آن نیاز داریم.

### تنظیم اولیه (یک‌بار)

۱. یک مخزن **خصوصی** بسازید، مثلاً `sobhansamadi-backups`.

۲. در Cloudflare یک API Token بسازید با دسترسی `D1:Read` روی همان حساب.

۳. یک Personal Access Token گیت‌هاب بسازید که فقط به مخزن خصوصی دسترسی
   نوشتن داشته باشد (Fine-grained → Contents: Read and write).

۴. یک عبارت عبورِ قوی برای رمزگذاری بسازید و **در پسورد‌منیجر ذخیره
   کنید**. اگر این عبارت گم شود، فایل‌های بک‌آپ برای همیشه غیرقابل
   خواندن‌اند — خودِ بک‌آپ سالم است ولی به درد هیچ‌کس نمی‌خورد.

۵. این چهار مقدار را در همین مخزن، در Settings → Secrets and variables →
   Actions اضافه کنید:

| نام | مقدار |
|---|---|
| `CLOUDFLARE_API_TOKEN` | توکن مرحله‌ی ۲ |
| `CLOUDFLARE_ACCOUNT_ID` | شناسه‌ی حساب Cloudflare |
| `BACKUP_REPO_TOKEN` | توکن مرحله‌ی ۳ |
| `BACKUP_REPO` | مثلاً `mehdifx21hoseini-debug/sobhansamadi-backups` |
| `BACKUP_PASSPHRASE` | عبارت عبور مرحله‌ی ۴ |

۶. یک بار دستی اجرایش کنید (تب Actions → Weekly DB Backup → Run
   workflow) تا مطمئن شوید کار می‌کند.

## بازگردانی

### از نسخه‌ی هفتگی

```
gpg --decrypt --output dump.sql backups/2026-09-01.sql.gpg
npx wrangler d1 execute sobhan-bot-db --remote --file dump.sql
```

### تمرینِ بازگردانی

**بک‌آپی که تستش نکرده باشیم، بک‌آپ نیست.** هر سه ماه یک بار:

۱. آخرین فایل را رمزگشایی کنید.
۲. در یک دیتابیس **آزمایشی** (نه پروداکشن) اجرایش کنید:
   `npx wrangler d1 create sobhan-restore-test` و بعد `--file dump.sql`.
۳. چند عدد را با پروداکشن مقایسه کنید: تعداد لیدها، شماره‌ها، مشترکین.
۴. دیتابیس آزمایشی را پاک کنید.

اگر این تمرین را انجام ندهید، اولین باری که واقعاً به بک‌آپ نیاز پیدا
کنید، همان اولین باری است که می‌فهمید کار می‌کند یا نه.

## چیزی که بک‌آپ نمی‌شود

کلیدها و توکن‌ها (توکن ربات، کلیدهای سرویس) در Secrets کلادفلر هستند و
هیچ‌جا نسخه‌ی دومی ندارند. اگر بروند فاجعه نیست — توکن ربات را BotFather
دوباره می‌سازد و بقیه را خودمان — ولی چند ساعت خرابی دارد. **جایشان
پسورد‌منیجر است، همین امروز.**
