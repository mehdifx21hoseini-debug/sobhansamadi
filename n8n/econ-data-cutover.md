# مرحله ۱: جمع‌آوری داده و تحلیل تقویم، بدون n8n

## چه چیزی جابه‌جا شد

| کار | قبل | بعد |
|---|---|---|
| تحلیل هوش مصنوعی | `WF-Econ-Explain` → Gemini | ورکر → Gemini، کش در D1 |
| تعطیلات | `WF-Economic-Calendar` | کران ساعتی ورکر → `date.nager.at` |
| رویدادهای تقویم | `WF-Economic-Calendar` | جاب ساعتی GitHub Actions → `POST /econ/ingest` |

## چرا فید تقویم از ورکر گرفته نمی‌شود

اولین طرح این بود که ورکر خودش هر دو منبع را بگیرد. تعطیلات جواب داد،
فید تقویم نه. اندازه‌گیری شده، در یک بازه‌ی چند دقیقه‌ای:

| فرستنده | پاسخ `nfs.faireconomy.media` |
|---|---|
| Cloudflare Worker، بدون User-Agent | ۴۲۹ |
| Cloudflare Worker، با User-Agent | ۴۲۹ |
| ران‌رِ GitHub Actions (`curl` ساده) | **۲۰۰** |
| سرور n8n | ۲۰۰ (سال‌هاست، ساعتی) |

فید پشت خودِ Cloudflare نشسته و درخواست‌های Workers را رد می‌کند. این
محدودیت **شبکه** است نه نرخ: صبر کردن، عقب‌نشینی، یا کم کردن دفعات هیچ
اثری ندارد.

الگوی GitHub Actions در همین مخزن تازه نیست — `ff-actuals.yml` دقیقاً به
همین دلیل از قبل آنجاست (آن یکی حتی به مرورگر واقعی نیاز دارد؛ این یکی
با `curl` باز می‌شود).

## جاب فقط یک لوله است

`ff-calendar.yml` فید را می‌گیرد و **خام** می‌فرستد. نرمال‌سازی، نگه
داشتن عدد واقعی و نوشتن، همه در `bot/src/econ/ingest.js` است. دلیلش
ساده است: هر منطقی که در YAML بنشیند، جایی است که نه تست دارد نه
به‌سادگی دیده می‌شود.

## دو قفل روی یک در

فیدِ سالم هرگز خالی نیست. آرایه‌ی خالی یعنی ساختار عوض شده یا صفحه‌ی خطا
برگشته — و نوشتنش یعنی پاک کردن تقویم. پس جاب پیش از ارسال بررسی می‌کند
و ورکر هم پیش از نوشتن؛ هیچ‌کدام به دیگری تکیه نمی‌کند.

## عدد «واقعی»

فید عدد واقعی را دیر - یا اصلاً - نمی‌آورد؛ آن‌ها از `ff-actuals.yml`
می‌آیند. بدون `preserveActuals`، هر اجرای ساعتی یک رشته‌ی خالی روی عددِ
منتشرشده می‌نوشت و در چشم کاربر عدد ظاهر می‌شد و یک ساعت بعد ناپدید.

## شناسه‌ی رویداد عوض نشد

`event_id` مو‌به‌مو با همان فرمول n8n ساخته می‌شود
(`FF_<تاریخ>_<slug عنوان>`). اگر عوض می‌شد، دفترِ ارسال همه‌ی رویدادهای
موجود را «تازه» می‌دید و برای هر کدام دوباره هشدار می‌فرستاد.

## کلیدها

```
/admin/econ-ingest?state=on|off      جمع‌آوری داده (رویدادها + تعطیلات)
/admin/econ-ingest?state=on&run=1    و همان لحظه تعطیلات را بگیر
/admin/econ-explain?state=on|off     تحلیل هوش مصنوعی
```

هر کدام جدا، چون دو ریسک متفاوت دارند: تحلیل فقط یک دکمه است، ولی
جمع‌آوری، مالکیت جدول رویدادها را عوض می‌کند. وقتی `econ_ingest` روشن
است، `syncFromN8n` از رویدادها و تعطیلات کنار می‌کشد تا دو نویسنده به
جان یک جدول نیفتند؛ برچسب‌ها همچنان از آنجا می‌آیند.

## راز لازم

`ECON_INGEST_KEY` به‌عنوان **GitHub repository secret**. اگر ست نشود،
ورکر درخواست را با ۴۰۱ رد می‌کند و جاب قرمز می‌شود — بی‌صدا شکست
نمی‌خورد. سمت ورکر، اگر `ECON_INGEST_KEY` نباشد به `ECON_EXPORT_KEY`
برمی‌گردد، پس ساختن یک راز تازه در کلادفلر لازم نیست.

## برگرداندن

`/admin/econ-ingest?state=off` — همان دقیقه `syncFromN8n` دوباره مالک
جدول می‌شود و n8n مثل قبل داده را می‌رساند. جاب GitHub را هم می‌شود
غیرفعال کرد، ولی لازم نیست: ورکر با کلید خاموش چیزی نمی‌نویسد.
